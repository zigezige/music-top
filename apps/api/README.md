# API service

When `DATABASE_URL` is absent, shares and issue reports use in-memory storage and are lost when the API process stops. Production startup requires `DATABASE_URL`, applies `migrations/001_shares.sql`, and uses PostgreSQL repositories.

## Catalog provider

Local development and production always use the QQ Music catalog provider. If `QQ_MUSIC_API_URL` is unset, the API starts the bundled `@sansenjian/qq-music-api` service on `127.0.0.1:3200` and connects the catalog provider to it. Set `QQ_MUSIC_API_PORT` to change that local port. Set `QQ_MUSIC_API_URL` to use an externally managed compatible service; when set, the bundled service is not started. There is no sample-catalog fallback, so an upstream failure is reported as an API error instead of showing non-QQ data.

`QQ_MUSIC_API_URL` sets the base URL for an externally managed, qq-music-api-compatible service. The default embedded service is the community-maintained `@sansenjian/qq-music-api` package, which listens on loopback and is not exposed to browser clients. The API searches QQ Music singers, reads album types, and retrieves the selected singer's songs in pages. The upstream song endpoint returns at most 60 entries per page, so requests are capped at 60 to avoid gaps. Only tracks associated with a recognized studio album, single, EP, compilation, or soundtrack are included; entries marked as live, instrumental, remix, cover, demo, preview, or clip versions, and entries whose recording type cannot be confirmed, are excluded. Album type is looked up from the singer's album list and, when missing, from album details. Numeric QQ version codes are not used because their meanings are undocumented and overlap between live and ordinary tracks. Repeated releases are merged by normalized title, credited artists, and duration when available, while the QQ song ID is retained for the selected entry. Album metadata prefers the earliest release with the most complete fields. Returned song, album, release-date, and cover metadata are mapped when available. The bundled community project is not an official QQ Music API; its README limits use to learning and research and prohibits commercial use. Confirm that this restriction and QQ Music's applicable service terms permit your deployment before production use. Data may be incomplete or inconsistent. The catalog API does not return audio, lyrics, or streaming URLs; users can report missing or misattributed songs.

Anonymous write requests to `POST /api/v1/shares` and `POST /api/v1/catalog-issues` share a per-client fixed window. Configure the budget with `API_ANONYMOUS_WRITE_LIMIT` (default `30`), `API_ANONYMOUS_WRITE_WINDOW_MS` (default `60000`), and `API_ANONYMOUS_WRITE_MAX_IP_BUCKETS` (default `10000`). The limiter stores at most the configured number of client buckets plus one shared overflow bucket. Once named buckets are full, new client identities share the overflow budget until capacity is reclaimed; this intentionally trades per-client precision for bounded memory under high-cardinality traffic. Expired bucket reclamation runs periodically, not as a full map scan on every request.

Forwarded client addresses are ignored by default. Set `API_TRUST_PROXY` only when the API is reachable exclusively through known trusted proxies. A numeric value configures the number of trusted proxy hops, for example `1`; the server translates it into a hop-aware trust function. A comma-separated value configures trusted proxy IPs/CIDRs, for example `10.0.0.0/8,192.0.2.10`. Fastify then derives the client address from forwarding headers only when the connection chain matches that configured trust. Never enable broad trust such as `true` when clients can connect directly, because they could choose their own `X-Forwarded-For` value.

`PORT` defaults to `3001`; `HOST` defaults to `0.0.0.0`.
